## What this is

VideoDart is a native **macOS** app (SwiftUI, Swift 6, no dependencies but Sparkle) that
downloads video via **yt-dlp** and converts it via **FFmpeg**. It installs both tools —
plus Deno, which YouTube's format signing requires — into Application Support on first
launch, so a user needs neither Homebrew nor a terminal. Two windows: the download queue,
and a converter with saveable presets.

## Commands

Build:
```sh
xcodebuild -project VideoDart.xcodeproj -scheme VideoDart \
  -configuration Debug -destination 'platform=macOS,arch=arm64' build
```

Run it (self-checks trap on launch if anything regressed — see below):
```sh
./build/Build/Products/Debug/VideoDart.app/Contents/MacOS/VideoDart
```

Release (signs, notarizes, staples, writes `appcast.xml` — see `NOTARIZING.md`):
```sh
./make-release.sh 0.4.0                    # tag v0.4.0
./make-release.sh 0.4.0 v0.4.0-beta.1      # pre-release under a beta tag
```

## Testing

**There is no test target.** `SelfCheck.run()` is called from the app's `init()` under
`#if DEBUG` and asserts its way through the parsers and argument builders. A failure traps
on launch, so "the app started" is the green check. Add checks there, in the existing
style, for anything with a branch in it.

What it covers, and why each one is there rather than being obvious: yt-dlp and FFmpeg
progress-line parsing (both tools report `N/A` for unknown fields in more than one
spelling), both argument builders, `cleanError` for each tool, timecode parsing, FFmpeg
output-path collision handling, and the on-disk shape of `queue.json` / `presets.json`.

**Decoding is deliberately lenient in both persisted models** (`DownloadJob`,
`ConvertPreset`): every key falls back to a default when absent. Synthesized decoding
throws on a missing key, and both stores silently discard a file they cannot read — so a
newly added field would wipe an existing user's queue or presets. SelfCheck decodes a
verbatim older on-disk payload to catch that; keep those cases when you add a field.

## Things that are the way they are on purpose

- **The three tools live outside the app bundle.** A binary inside a signed bundle can't be
  replaced without invalidating the signature, which would freeze yt-dlp between app
  releases. `ToolInstaller` puts them in Application Support instead.
- **`AppSupport.directory` is the only place an on-disk path is decided**, and the only
  place the 0.3.0 VideoDownloader → VideoDart migration lives.
- **`ConvertQueue` is serial and not persisted**, unlike `DownloadQueue`. FFmpeg already
  saturates every core, and a conversion reads a local file, so there is nothing to resume.
- **Codec pickers are filtered against `ffmpeg -encoders`** on the resolved binary. That
  cache refuses to memoize an empty result, so installing FFmpeg from the in-app banner
  doesn't leave the menus blank until relaunch.
- **`FFmpeg.outputURL` never returns the source path.** Converting MP4 to MP4 in place
  would otherwise truncate the original. Don't "simplify" it.
- **`Info.plist` at the repo root holds only Sparkle's two keys.** Everything else is
  generated by Xcode and merged in; `INFOPLIST_KEY_` build settings only work for keys
  Apple knows about, and `SUFeedURL`/`SUPublicEDKey` are not among them.
- **`ARCHS` is passed on the `xcodebuild` command line** in `make-release.sh`. The same
  value in `project.pbxproj` is silently ignored and yields an arm64-only binary.
