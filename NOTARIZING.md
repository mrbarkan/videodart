# Releasing

`./make-release.sh <version>` does the whole release: build, sign, notarize and staple
both the app and the DMG, then write `appcast.xml` for Sparkle.

    ./make-release.sh 1.1

Send `dist/VideoDart.dmg` — mounting and launching both work offline because each
is stapled separately. The script prints the two commands that publish the update:

    gh release create v1.1 dist/VideoDart.dmg --repo mrbarkan/videodart ...
    git add appcast.xml && git commit -m "Release 1.1" && git push

Existing copies check `appcast.xml` on the default branch, so nothing is offered to
anyone until that commit is pushed. Order matters: upload the release asset first, or
the first person to check will follow a link to a file that is not there yet.

The version you pass becomes `CFBundleShortVersionString`. The build number Sparkle
actually compares is a UTC timestamp the script generates, so there is no counter to
remember to bump and no way to ship two builds that look equal.

## One-time: notarization credentials

The script needs a `notarytool` keychain profile. It wants an app-specific password from
https://appleid.apple.com (Sign-In and Security -> App-Specific Passwords). Run this
yourself — it prompts for the password:

    xcrun notarytool store-credentials notarytool \
      --apple-id "<your-apple-id-email>" \
      --team-id L26TPPMPF3

## One-time: Sparkle signing key

Updates are signed with the EdDSA key already in the login keychain as "Private key for
signing Sparkle updates" — the same one the other apps use. Its public half is baked into
`Info.plist` as `SUPublicEDKey`; a copy signed with any other key is refused by every
installed app, so do not generate a new one.

The first `sign_update` run of a session raises a keychain prompt. Click **Always Allow**
once and later releases are silent. To check which key is in use:

    ./build/SourcePackages/artifacts/sparkle/Sparkle/bin/generate_keys -p

## Where the update settings live

`Info.plist` at the repo root holds only `SUFeedURL` and `SUPublicEDKey`. Everything else
is still generated by Xcode and merged into it at build time — `INFOPLIST_KEY_` build
settings only work for keys Apple knows about, and Sparkle's two are not among them.
